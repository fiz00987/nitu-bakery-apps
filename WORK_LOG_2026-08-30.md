## 3. Customer app — payment option rework (grey auto box + read-only due box)

**Request:** after typing the total (e.g. ৳1000) and picking bKash/Nagad/Bank + 50% advance, the amount should auto-calculate into a **grey, bold, editable** box; tapping it must pop a warning that the figure was auto-calculated **with the gateway charge** and the **admin should be informed before changing it**; right below, a separate **due amount** (the rest, e.g. ৳500) auto-calculated, **greyed out and non-editable**.

### `customer-app/index.html`
- Payment amount input `#f-advance` → class `advance-input` (grey `#eee`, bold 16px) + `onclick/onfocus="onAdvanceClick()"`. Label re-worded: "আপনি কত টাকা পাঠাতে চান? *" / "How much do you want to send? *".
- Removed the pink `#advance-calc-box` breakdown and the old `#due-panel` (replaced by the new pair). Top `#calc-box` (cake price / delivery / total) kept.
- New `#due-field` right below: read-only `#f-due` (`input.due-input`, grey, `cursor:not-allowed`, `onfocus="this.blur()"`, `tabindex="-1"`) + `#due-hint` (pay-later note + separate delivery charge). Hidden until an amount exists.
- Warn popup `#advance-warn-popup` body is now dynamic (`#advance-warn-msg` + `#advance-warn-ok`): "এই পেমেন্ট অটোমেটিক হিসাব করা হয়েছে — বিকাশ/নগদ চার্জসহ। পরিবর্তন করার আগে **অ্যাডমিনকে জানান**।" (method-aware, both languages).
- CSS: `input.advance-input`, `input.due-input`, `.due-field(.show)`; spinner arrows hidden for `#f-advance` too; dead `.due-panel` rules removed.

### `customer-app/app.js`
- **`#f-advance` now holds what the customer SENDS: base advance + gateway charge** (e.g. 50% of ৳1000 via bKash → ৳500 + ceil(500×1.82%) = ৳10 → box shows **510**). Auto-fill on 50%/100% click and on price/method changes (`setAdvanceType` → `recalcPrice` auto path).
- **Editable, no more snap-back**: the old manual-edit guard (value forced back) is gone. Tapping the box (`onAdvanceClick`, only when an auto-calc is active) shows the warn popup; after that the customer may type any amount.
- **`#f-due`** = `total − base advance`, auto-calculated, read-only (e.g. ৳500). Shows ৳0 on full payment; delivery charge noted separately.
- Helpers: `getGatewayRate()`, `splitSend()` (splits a typed amount so `charge = ceil(base × rate)` and `base + charge = send` — same ceil model as the admin app), `onAdvanceClick()`, `showAdvanceWarn()`. State: `lastAutoSend` / `lastAutoBase` (replace `lastAutoAdvance`).
- Hint under the box: auto → "অটো হিসাব: ৫০% অগ্রিম ৳500 + বিকাশ চার্জ ৳10 = পাঠাতে হবে ৳510"; custom → "নিজের হিসাব: …".
- `submitOrder`: derives `advance` (base) / `charge` / `advanceTotal` (= send amount, now an exact integer) / `dueAmount`; adds `advanceCharge` (admin popup already displays it) and `advanceAutoTotal` (the original auto amount, recorded when the customer deviated — so the admin can see the change). Surprise validation still works (send ≥ total enforces full payment).
- `resetForm`: clears `lastAutoSend/lastAutoBase` and hides `#due-field`; EN label override for `#f-advance` removed (data-bn/data-en drive both languages).
